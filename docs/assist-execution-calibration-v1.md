# 助攻与投篮执行校准 v1

这一轮把助攻从“进攻路线的固定属性”改成命中投篮之后的独立条件事件，并将结果冻结为
`demo-0.6.0`。目标是修正统计生成机制，而不是用总得分反推命中率。

## 新的因果顺序

```text
进攻计划
→ 终结路线与球员
→ 出手区域
→ 防守干扰/盖帽
→ 命中
→ 是否形成助攻
→ 助攻球员
→ 统计账本
```

`assist_resolution` 按终结的创造模式给出基础助攻概率：

- `SELF_CREATED`
- `SCREEN_PARTNER_FEED`
- `SPOT_UP_FEED`
- `OFF_BALL_MOVEMENT_FEED`

固定传球路线仍将计划中的持球人作为候选助攻者；自主持球终结若被判定为助攻，则从其余四名
进攻球员中抽样。球员版策略使用组织能力和进攻决策调节候选权重。助攻者不能是终结者，也
必须属于进攻阵容。

## 兼容与审计

- 参数结构升级到 `demo-v1.4`；加载器仍接受 `demo-v1.3`。
- `demo-v1.3` 保留旧语义：固定传球路线必定助攻，自主创造不记助攻。
- 单行动段序列化升级到 v2，显式保存 `assister_id`。
- v1 事件仍可读取，并按旧路线语义恢复助攻者。
- 新随机槽只追加在既有槽之后，不改变旧节点的随机地址。

结构迁移由独立命令完成：

```powershell
.\tools.ps1 parameters-add-assist `
  data/model_schema_demo_v1_4.json `
  data/model_parameters_demo_0.5.0.json `
  experiments/calibration/assist-node-v1.json `
  work/candidates/assist.json
```

数值覆盖不能新增结构节点，因此助攻迁移和后续数值校准在审计记录中是两个不同操作。

## 候选扫描

在助攻初始候选上，对三分命中基础概率做固定种子的 30 场扫描：

| 三分命中基础参数 | 三分命中率 | 总命中率 | 每百回合得分 | 助攻/命中 |
| ---: | ---: | ---: | ---: | ---: |
| 0.029 | 36.43% | 46.57% | 107.01 | 65.22% |
| 0.030 | 37.16% | 46.87% | 107.86 | 65.36% |
| 0.031 | 38.35% | 47.37% | 109.20 | 65.60% |

选择 `0.030`。随后只对盖帽竞争风险和失误竞争风险做局部居中，不再用命中率补足模型中
尚不存在的罚球得分。
