# 第一轮结构校准 v1

这一轮只校准事件构成，不调整投篮命中参数。旧的 `demo-0.4.0` 基线继续保留，
新结果冻结为 `demo-0.5.0`，两者承担不同的回归责任。

## 首先修正审计夹具

旧批量命令把 `player_profile_v1.json` 中同一个移动射手复制成十名球员。该球员具有：

```text
three_point_shooting = 90
shot_zone_mix.three = 95
offensive_rebounding = 25
rim_protection = 25
block_chase = 25
```

因此旧基线的 90.46% 三分出手与极低盖帽/篮板率不能直接解释为全局参数错误。

新增的 `PlayerLineup v1` 输入严格包含五个不同档案。当前校准夹具为：

```text
examples/calibration_lineup_v1.json
```

它由合成的主控、移动侧翼、双向侧翼、内线前锋和护框中锋组成，不使用真实球员姓名。
批量运行清单现在把该输入及其 SHA-256 一并登记；旧的单球员模板格式仍兼容。

## 可审计参数覆盖

新增命令：

```powershell
.\tools.ps1 parameters-overlay `
  data/model_schema_demo_v1_3.json `
  data/model_parameters_demo_0.4.0.json `
  experiments/calibration/zone-extra-v1.json `
  work/candidates/zone-extra.json
```

覆盖文件只能修改已经存在的 `nodes` 或 `rules` 数值叶子。它不能修改元数据路径、
新增节点、替换整个对象、重复写同一路径或写入非有限数。物化后会立即执行完整参数契约校验。

## 区域候选扫描

固定其余节点后，以相同种子对三档区域候选各运行 20 场：

| 候选 | 三分 | 篮下 | 中距离 |
| --- | ---: | ---: | ---: |
| mild | 57.32% | 28.16% | 14.51% |
| medium | 52.33% | 30.57% | 17.10% |
| strong | 46.85% | 33.60% | 19.56% |
| extra | 40.73% | 37.07% | 22.20% |

最终选择 `zone-extra-v1`。它不是用命中率反推区域，而是直接修正区域条件分布。

## 事件率校准

`events-v1` 在区域候选之上只做两类改变：

- 提高三类进攻计划中失误相对投篮机会的竞争风险；
- 将篮板防守侧上下文倍率从 `3.0` 调整到 `2.2`。

盖帽基率和全部 `shot_make` 参数保持冻结。区域结构变化本身已经把盖帽率带到目标附近。

## 独立复验与冻结

独立种子 `20260724`、100 场、19,200 个球队回合的结果：

| 指标 | demo-0.5.0 | NBA目标 | 状态 |
| --- | ---: | ---: | --- |
| 三分出手份额 | 41.19% | 42.12% | 区间内 |
| 失误率 | 14.97% | 14.28% | 区间内 |
| 抢断率 | 8.43% | 8.20% | 区间内 |
| 进攻篮板率 | 26.29% | 25.21% | 区间内 |
| 每百回合得分 | 113.23 | 113.69 | 区间内 |
| 总命中率 | 48.74% | 46.72% | 区间内 |
| 三分命中率 | 43.08% | 36.02% | 偏高 |
| 助攻/命中 | 48.25% | 63.68% | 偏低 |
| 盖帽率 | 5.93% | 5.46% | 轻微偏高 |

新冻结输入与基线：

```text
data/model_parameters_demo_0.5.0.json
data/baselines/model-audit-demo-0.5.0.json
experiments/model-audit-demo-0.5.0.json
experiments/model-audit-demo-0.5.0-regression-gates.json
```

真实性门禁仍失败，不能宣称完成校准。下一层应分别处理投篮执行和助攻生成；
尤其助攻目前是由路线类别直接决定的布尔属性，缺少一次独立的助攻解析节点。

当前夹具只是稳定的合成参考阵容，不是联盟球员分布。未来应增加多阵容人口抽样，
避免任何一套五人能力值成为隐含的“联盟平均”。
