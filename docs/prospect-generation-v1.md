# Annual prospect generation v1

Status: local release candidate, 2026-07-26.

## Purpose

`prospect-generation-v1` supplies a deterministic incoming player class for every manager
experiment season that does not already contain a complete prospect pool. It removes the need
to preload all future draft classes into the initial league state.

## Stable identity

Player identity is derived from the reserved high-ID namespace, draft year, and class slot:

```text
player_id_base + draft_year * 100 + slot
```

Generation rejects collisions instead of shifting identifiers. This keeps a prospect's identity
stable when unrelated players, templates, or execution order change.

## Player construction

Each class contains a governed number of creator, shooter, defender, interior, or balanced
prospects. Every one of the 20 abilities receives an independently addressed value. Archetypes
apply bounded semantic adjustments to relevant fields; no global overall rating is stored.

Each ability also receives its own potential ceiling above current ability. Age, size class,
growth rate, peak window, decline resistance, and consistency use separate semantic random
addresses. Template ordering cannot change the generated class; templates supply only the
existing immutable tendency structure.

Default bounds:

- four prospects;
- age 18–21;
- current ability 42–74;
- potential gain 6–24 per field;
- growth rate 55–95;
- decline resistance 35–85;
- consistency 60–95.

## League integration

`manager-league-adapter-v1` checks the prospect pool at the beginning of every requested
season. A full preloaded class is preserved. An empty pool receives a class for the following
draft year, using a seed derived without the experiment arm label so incumbent and Shadow see
identical prospects.

Partial classes are rejected because silently mixing generated and supplied prospects would
make class strength and slot identity ambiguous. Generated class details are retained in the
season executor audit payload.

## Known limits

- Tendencies are inherited from canonical profile templates rather than generated by archetype.
- International/stash eligibility, scouting uncertainty, college statistics, injuries, and
  draft withdrawal are not modeled.
- The generator does not create roster space; draft capacity still follows canonical contract
  and roster rules.
