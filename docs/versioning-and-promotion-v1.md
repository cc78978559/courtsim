# 版本与正式基线晋级契约 v1

CourtSim 将引擎、模型结构、数值参数和持久化格式分别版本化。任何一个版本变化都不能
静默改变其他版本的语义。

## 版本轴

### 引擎版本

Python 包使用 SemVer，例如 `0.1.0`。

- patch：不改变公开数据或模拟语义的修复；
- minor：向后兼容的公开能力、命令或读取支持；
- major：不兼容的公开 API、CLI 或持久化边界。

### 模型结构版本

模型结构使用 `demo-v1.N`。概率节点、状态机分支、事件因果顺序或随机槽发生变化时
必须创建新结构版本。已发布枚举编号和随机槽只能追加，不能重排。

### 参数版本

参数使用 `demo-X.Y.Z`。

- major：新的正式模型家族或不兼容的校准语义；
- minor：新机制、重新校准或新的正式候选；
- patch：不改变模型输出的元数据修正。

参数必须显式声明兼容的结构版本和引擎范围。

### 格式版本

事件、manifest、实验、目标集和治理清单各自使用整数 `format_version`。读取旧格式
只能通过显式兼容逻辑，禁止根据文件名猜测或静默升级。

## 当前发布清单

`governance/current-release.json` 是机器可读的正式入口，记录：

- 当前引擎、结构和参数版本；
- 结构、参数和基线的文件 SHA-256 与语义哈希；
- 正式 audit、实验清单、回归门禁和真实性目标；
- 晋级日期和来源 PR。

CLI 默认值、README、`PROJECT_STATUS.md` 和 `docs/current-state.md` 必须与该清单一致。
CI 会验证清单引用、哈希、真实性评分和回归门禁。

## 晋级流程

一个候选版本只有满足全部条件后才能标记为 `frozen`：

1. 结构、参数、迁移规格和敏感性证据已版本化；
2. 使用未参与调参的独立主种子运行至少 100 场完整事件审计；
3. worker 数、分片和顺序不改变规范事件或 audit；
4. 完整 manifest 通过哈希验证；
5. 所有 active 真实性目标和候选回归门禁通过；
6. 旧结构、参数、事件和基线兼容测试继续通过；
7. baseline、实验清单和回归门禁进入版本库；
8. 更新 `governance/current-release.json`、CLI 默认值和当前状态文档；
9. Linux 与 Windows CI 全部通过；
10. 由人工审查 PR 后晋级，禁止实验矩阵自动提升正式版本。

`aggregate-only` 可用于候选扫描和性能分析，但不能作为正式冻结证据。

## 回退

若正式版本出现缺陷，应新增修复提交或新版本，不得重写已发布 baseline。回退时只修改
当前发布清单和 CLI 默认指针，并保留问题版本的文件、哈希、实验记录和原因说明。

## 发布检查

引擎发布标签使用 `v<engine-version>`。创建标签前必须确认：

- 工作树干净，目标提交位于 `main`；
- 当前发布清单测试和完整质量门禁通过；
- `CHANGELOG.md` 已记录用户可见变化；
- GitHub 上 Linux/Windows required checks 均成功；
- 标签指向经过审查的合并提交。
